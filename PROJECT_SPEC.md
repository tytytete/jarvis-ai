## 1. Обзор проекта и Цели

Цель проекта — создание высокопроизводительного, минималистичного и экономичного персонального ИИ-ассистента («Джарвис») для локального управления ПК. 

Ключевая идея архитектуры — **двухуровневая обработка команд (Dual-Path Processing)**:
1. **Fast-Path (Локальный Python NLU / Regex):** Выполнение мгновенных бытовых команд (0 токенов, задержка 10–50 мс) без обращения к внешним API.
2. **Slow-Path (LLM API):** Обращение к нейросети только для сложных, нелинейных, мульти-шаговых задач или глубокого анализа контекста.

### 2.1. Операционная система
* **Текущий приоритет:** Windows 10 x64.

* **Динамическая запись состояния:** Найденные параметры экранов скрипт должен автоматически вносить в соответствующий раздел этого ТЗ при первом запуске.

## 3. Голосовой Стек (Voice Control)

### 3.1. Speech-to-Text (STT)
* **Локальная обработка:** Использование быстрых офлайн-решений для распознавания речи (например, `Faster-Whisper`, `Vosk` или встроенный Windows Speech API).
* **Режимы активации:**
  * Wake-word (активация по фразе-ключу "Джарвис").
  * Push-to-Talk (активация по системной горячей клавише).

### 3.2. Text-to-Speech (TTS)
* **Быстрый синтез:** Использование лёгких локальных решений (`pyttsx3`, `piper-tts`) или высококачественного бесплатного стриминга (`edge-tts`).
* **Параллелизм:** Озвучка работает в асинхронном режиме и не должна блокировать главный поток выполнения команд или прослушивания.

## 4. Оптимизация Производительности и Взаимодействие с LLM

### 4.1. Разделение потоков (Fast-Path vs Slow-Path)

| Тип задачи | Исполнитель | Расход токенов | Задержка |
| :--- | :--- | :--- | :--- |
| Медиа (плей, пауза, громкость, треки) | Python Win32 Media Keys | **0** | ~5-15 мс |
| Запуск ПО / Переключение окон | Python `subprocess` + `win32gui` | **0** | ~20-50 мс |
| Системные сочетания (Win+D, Alt+Tab, Alt+F4) | Python `pyautogui` / `pynput` | **0** | ~10 мс |
| Сложный анализ текста / планирование | External LLM API | Согласно тарифу | ~500-1500 мс |

### 4.2. Локальный Fast-Path (NLU / Regex Engine)
Перед отправкой запроса в LLM распознанный текст проходит через локальный роутер:
* **Медиа-клавиши:** Использование скан-кодов клавиатуры Windows (`VK_MEDIA_PLAY_PAUSE`, `VK_VOLUME_UP` и др.).
* **Запуск приложений:** Поиск по системным реестрам, Win+R алиасам, папкам Start Menu и пользовательскому словарю путей (`config/apps.json`).
* **Фокус окон:** Использование `win32gui.EnumWindows` и `SetForegroundWindow` для моментального переключения на нужные приложения.

### 4.3. Slow-Path (LLM API & Tool Calling)
* **Формат обмена данными:** Для вызова локальных Python-функций LLM обязана использовать нативный механизм **Tool Calling** (Function Calling) API или возвращать команды в строгом формате JSON. Никакого неструктурированного текста в ответах с действиями.
* **Context Caching:** Использование кэширования промптов на стороне API (если поддерживается моделью) для передачи неизменяемого системного промпта со списком инструментов.
* **Локальный OCR:** Предварительное распознавание текста на экране средствами `EasyOCR`, `RapidOCR` или Tesseract для вычисления координат UI-элементов без отправки тяжелых Vision-запросов. Скриншоты в API передаются *только* по прямому запросу LLM.

## 5. Отказоустойчивость и Обработка Ошибок (Fallback)

Скрипт должен быть надежным и не падать при локальных сбоях:
1. **Сбой API LLM:** Если API недоступно или превышен таймаут, ИИ-ассистент должен сообщить об этом голосом через TTS и переключиться в режим "только Fast-Path" (выполнение только базовых локальных команд).
2. **Сбой OCR/Координат:** Если локальный `EasyOCR` не может найти запрошенный элемент на экране, скрипт должен вернуть ошибку в LLM, чтобы нейросеть могла запросить скриншот для Vision-анализа или попросить пользователя уточнить команду.
3. **Безопасное прерывание:** Должна быть предусмотрена "Panic Button" (горячая клавиша, например, `Ctrl+Alt+Shift+Q`), которая мгновенно прерывает любые действия агента (скрипты автоматизации, движение мыши, речь TTS).

### 7.5. Защита от опечаток в Fast-Path
Ведущий глагол команды нормализуется по словарю синонимов + фаззи-сравнение

интентов (например, «включи»/«выключи») защищены от кросс-подмены, чтобы не
терять точность. Пример из сессии: `открткрой дискорд` → `open_app` (Discord).

### 7.6. Память и краткость Slow-Path
- Контекст: нейросети передаются 2 предыдущих сообщения диалога (вопрос+ответ)
  через `input` как список сообщений (Responses API). Хранится в памяти процесса
  (REPL / daemon).
- Краткость: системный промпт требует отвечать одной короткой фразой/предложением,
  без списков и лишних пояснений, если не попросили подробности.

## 9. Голос Джарвиса (XTTS v2)

### 9.1. Что такое XTTS и как работает
- **XTTS v2** — end-to-end нейросетевая модель TTS от Coqui, поддерживает **17 языков** (включая русский) и **zero-shot клонирование голоса**: модель берёт образец речи (6+ секунд) и говорит новым текстом «тем же голосом».
- Оригинальный репозиторий Coqui TTS заброшен; поддерживаемый форк и PyPI-пакет — **`coqui-tts`** (репозиторий `idiap/coqui-ai-TTS`). Актуальная версия 0.27.x.
- Клонирование голоса: в API передаётся `speaker_wav=<аудио>`, и модель воспроизводит тембр этого диктора при синтезе любого текста.

### 9.2. Интеграция в проект
- **Движки озвучки** (`config/settings.json` → `tts_engine`):
  - `say` — системный macOS `say`, мгновенно и офлайн (значение по умолчанию);
  - `edge` — Microsoft Edge TTS (`edge-tts`), нейросетевой голос ~1-2 с, нужен интернет;
  - `xtts` — клонированный голос из `voice.mp3`, медленный на CPU (~5-10 с на фразу), opt-in.
- XTTS остался как опция, но **не используется по умолчанию** из-за медленного CPU-синтеза.
- Модуль `core/voice/tts.py`:
  - движок **`tts_models/multilingual/multi-dataset/xtts_v2`**;
  - голос берётся из **`voice.mp3`** (корень проекта, настраивается через `settings.json` → `tts_reference_voice`);
  - если `voice.mp3` отсутствует — синтез идёт дефолтным голосом XTTS;
  - если XTTS/torch не установлены или модель не загрузилась — фолбэк на системный macOS `say`;
  - синтез и воспроизведение (`afplay`) выполняются в фоновом потоке, не блокируя Fast-Path и прослушивание.
- Настройки `config/settings.json`: `tts_engine` (`auto`/`say`/`xtts`), `tts_reference_voice`, `tts_language` (`ru`).
- Модель XTTS предзагружается в фоне при старте (`preload()` в `main.py`), чтобы первый ответ не ждал ~20 с.
- **О DeepSeek:** модель `ds/deepseek-v4-flash` через anymodel.org **не имеет доступа в интернет** (нет веб-поиска), поэтому вопросы про погоду/актуальные события честно отвечает «нет доступа». Это ограничение API, а не сбой.
- `voice.mp3` добавлен в `.gitignore` (личная запись голоса не коммитится).

### 9.3. Установка зависимостей (macOS arm64)
```bash
.venv/bin/pip install torch==2.5.1 torchaudio==2.5.1
.venv/bin/pip install coqui-tts
.venv/bin/pip install "transformers<5"
```
> При первом запуске XTTS скачивает веса модели (~1.87 ГБ) в `.cache/tts`.

### 9.4. Проверенные ограничения (важно)
- **torch 2.5.1, а не 2.9+:** на torch >= 2.9 coqui-tts требует `torchcodec`, который тянет системный FFmpeg (`libavutil`). На 2.5.1 используется `torchaudio`, лишний FFmpeg не нужен.
- **transformers < 5:** transformers 5.x удалил `transformers.pytorch_utils.isin_mps_friendly`, из-за чего падает импорт XTTS. Рабочая версия 4.57.x.
- **Синтез на CPU:** вокодер XTTS на Apple Silicon падает на MPS (`Output channels > 65536 not supported`), поэтому в `tts.py` зафиксирован `device="cpu"`. Модель грузится ~20-25 с (один раз, в фоне), синтез короткой фразы ~4-7 с.
- Модель кэшируется в `.cache/tts` (добавлено в `.gitignore`), `voice.mp3` — личный голос, не коммитится.

## 10. Инструменты Slow-Path (Tool Calling)

DeepSeek (`ds/deepseek-v4-flash` через anymodel.org) поддерживает **Function Calling**:
модель сама решает, какой локальный инструмент вызвать, мы выполняем его и отдаём
результат обратно — в финальном ответе модель использует факты из инструмента.

### 10.1. Реализация
- `core/tools.py`: схемы инструментов (`TOOL_SPECS`) + исполнитель `execute_tool(name, args)`.
- `core/llm_client.py`: цикл tool calling (запрос → `function_call` → выполнение → `function_call_output` → повтор), лимит 5 циклов.
- `main.py`: передаёт `TOOL_SPECS`/`execute_tool` в Slow-Path.

### 10.2. Набор инструментов
- `web_search` — поиск в интернете (DuckDuckGo, с ретраями и фолбэк-эндпоинтом).
- `create_file` / `append_file` / `read_file` / `list_directory` — работа с файлами (пути от `~`).
- `current_time` / `current_date` — время и дата.
- `open_url` / `open_application` — браузер и приложения.
- `calculate` — безопасная арифметика.
- `run_shell` — выполнение shell-команды (использовать осторожно).

### 10.3. Ограничение веб-поиска
- DuckDuckGo HTML — бесплатный, без ключа, но иногда rate-limit (`Connection reset`). Поэтому в `web_search` два эндпоинта + ретраи; при полном сбое модель отвечает, что не смогла найти.

## 11. Голосовой ввод (STT + wake-word «Джарвис»)

### 11.1. Как работает (архитектура «как Siri»)
- Офлайн-распознавание на **Vosk** (модель `vosk-model-small-ru-0.22`, ~45 МБ).
- **Wake-word:** постоянно слушаем микрофон и ищем «Джарвис» (варианты: «джарвис», «жарвис», «jarvis»).
- После срабатывания: короткий звуковой отклик (`Ping.aiff`) → слушаем **команду** (до ~1.5 с тишины или лимита 8 с) → текст уходит в `dispatch()`.
- Команда, сказанная сразу после wake-word в одной фразе («Джарвис открой терминал»), тоже подхватывается.

### 11.2. Запуск
```bash
./jarvis --listen
```

### 11.3. Ресурсы
- Модель грузится один раз; Vosk small в фоне занимает ~50-100 МБ и умеренную долю ЦП.
- Если нужен минимальный idle-расход — следующий шаг: заменить wake-word на Porcupine (встроенный «Jarvis»), а Vosk включать только после срабатывания.

### 11.4. Конфиг
- `settings.json` → `stt_model_path` (по умолчанию `.cache/vosk-model-small-ru-0.22`).
- Wake-word и пороги — в `core/voice/stt.py` (`WAKE_WORDS`, `timeout`, `silence`).

### 11.5. Установка
```bash
.venv/bin/pip install vosk sounddevice
curl -L -o /tmp/vsm.zip https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip
unzip -o -q /tmp/vsm.zip -d .cache
```

## 12. Правила поведения (протокол команд)

- **Fast-Path** ловит простые локальные команды, 0 токенов.
- Если локальная команда **не выполнилась** → фраза передаётся **ИИ** (с инструментами, включая `run_shell`).
- Если ИИ решил задачу — отвечает результатом.
- Если ИИ **не знает, как решить** — отвечает ровно `0`, и программа выводит: **«Я не знаю, как это решить»**.
- **Sentinel:** ответ ИИ, состоящий ровно из `0`, интерпретируется как «не могу решить».

### Ограничения/нюансы, важные для будущих исправлений
- `osascript` возвращает код выхода 0 даже при ошибке → проверять **stderr** (см. `MacSystem._osascript`).
- Закрытие нескольких приложений («закрой всё / всё кроме X») — не Fast-Path, отдаётся ИИ.
- JSON-конфиги допускают `//`-комментарии и висячие запятые (см. `core/config.py`).

## 13. Slow-Path: модели и защита от «мусорных» ответов

### 13.1. Проблема провайдера (2026-09-30)
- `ds/deepseek-v4-flash` на anymodel.org стал возвращать **случайные английские цитаты** («Where there is a will…», «A journey of a thousand miles…») вместо ответа — примерно в 75-80% запросов.
- Это баг/деградация на стороне провайдера, не нашего кода.

### 13.2. Решение
- **Модели (жёсткий порядок, заданы пользователем):** `ds/deepseek-v4-flash` → `ds/deepseek-v4-pro` → `am/free`. Начинаем слева, при сбое/мусоре двигаемся вправо. Другие модели использовать нельзя.
- **Авто-fallback вправо:** если модель вернула мусор, пустой ответ ИЛИ ошибку (HTTP/сеть/таймаут) — сразу переключаемся на следующую справа, без лишних затрат токенов.
- **Детектор мусора** `_looks_like_junk()` в `core/llm_client.py`: ответ без кириллицы и с ≥4 английскими словами считается мусором и не попадает к пользователю.

### 13.3. Конфиг
`.env` → `ANYMODEL_MODEL` (primary) и `ANYMODEL_FALLBACK` (через запятую).

## 14. Зрение (скрин по запросу)

### 14.1. Как работает
- Инструмент **`look_at_screen`** (`core/tools.py`): делает скриншот `screencapture` → локальный **OCR** (RapidOCR) извлекает текст.
- Если ИИ задал конкретный вопрос о картинке — скрин отправляется vision-модели `am/free` (единственная из трёх разрешённых, кто видит изображения).
- Никаких постоянных скриншотов — только по запросу пользователя/ИИ.

### 14.2. Права
- Для скриншотов macOS требует права **«Запись экрана»** для терминала:
  `Системные настройки → Конфиденциальность → Запись экрана`.
- Скриншот — временный файл, удаляется сразу после обработки.

### 14.3. Только OCR (без vision-модели)
- DeepSeek — текстовая модель и не видит изображения. Используем только локальный RapidOCR (без токенов) — он надёжнее и экономичнее `am/free`.
- `question`-аргумент инструмента пока принят для совместимости, но обрабатывается OCR.

## 15. Допуск опечаток (биграммы)

- `utils/fuzzy.py`: близость слов по **биграммам** (группам из 2 букв), коэффициент Dice.
- В `Router._resolve_alias` имя команды подбирается: точный alias → биграммный подбор по ключам alias → подбор по каноническим именам приложений.
- Порог `threshold=0.55` (в `find_best`): «телеграммм»/«телеграмм» → Telegram, «дискорт» → Discord, «тирминал» → Terminal, «вацап»/«вотсап» → WhatsApp.
- Точные слова не подменяются (проверено: 45 alias-ключей, 0 ложных подмен).
